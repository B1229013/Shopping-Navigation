# 定位（Localization）檔案索引 — 給同學參考

> 用途：快速找到「定位」相關的程式與資料在哪裡、各自負責什麼。
> 方法論、各方法準確率、元件去留判定請看 [定位方法彙整與測試規劃.md](定位方法彙整與測試規劃.md)。
>
> **一句話現況**：正式系統的定位主力＝**融合定位（DINOv2 視覺 + 物件 + OCR）**，單張 Top-1 ≈ 66% / Top-5 ≈ 90%。
> 舊的 WGM 九宮格仍留著，但**只在融合定位失敗時當退回（fallback）**，正常不會用到。

---

## 1. 正式系統會用到的檔案（在 request 路徑上）

定位是「拍一張照片 → 判斷目前在地圖的哪個節點」。正式流程都在 `backend/server/` 內。

| 檔案 | 角色 | 關鍵進入點 |
|------|------|-----------|
| [server/server.py](server/server.py) | 串接點：先跑融合定位，失敗才退回 WGM | 分支在 `server.py:738` 起 |
| [server/locate_fusion.py](server/locate_fusion.py) | **主線**：融合定位（視覺+物件+OCR，權重 5:0.5:0.5） | `fusion_localize_for_server`、`build_fusion_index`、`localize_fusion` |
| [server/dino_embed.py](server/dino_embed.py) | 融合用的視覺向量（DINOv2，lazy 載入；載入失敗回 None 安全退回） | `embed_image` |
| [server/locate_v2.py](server/locate_v2.py) | **fallback**：WGM 九宮格定位；也提供被融合複用的文字 embedding | `localize_photo`、`_weighted_grid_match`、`_embedding_sim`、`ensure_embeddings` |

**上游依賴（提供定位輸入）**

| 檔案 | 提供什麼 |
|------|---------|
| [server/perception.py](server/perception.py) · [server/vlm.py](server/vlm.py) | 物件偵測結果（det_dicts） |
| [server/ocr.py](server/ocr.py) | OCR 文字 tokens |
| [server/topomap_v2.py](server/topomap_v2.py) | 拓樸地圖（節點與物件資料來源） |

> ⚠️ 若要移除 WGM，`locate_v2.py` 的 `_embedding_sim` / `ensure_embeddings` **仍被融合定位複用，不能一起刪**。

## 3. 實驗與評測腳本（研究用，不在部署路徑）

## 看定位怎麼運作，最快路徑

1. 先讀 [定位方法彙整與測試規劃.md](定位方法彙整與測試規劃.md) 了解「為什麼選融合定位」。
2. 看 [server/locate_fusion.py](server/locate_fusion.py) 的 `fusion_localize_for_server`（正式進入點）。
3. 看 [server/server.py:738](server/server.py) 的分支，了解融合與 WGM 的取捨。
4. 想重現 66%：跑 [run_fusion_live.py](run_fusion_live.py)。
