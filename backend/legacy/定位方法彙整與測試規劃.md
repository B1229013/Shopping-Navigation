# 定位檢索：方法彙整與測試規劃（最終版）

> 測試條件：單張照片定位（使用情境＝拍一張、**不知道方向**）；測試集＝0916家樂福 268 張實拍照片（未參與建圖）；
> GT＝人工確認過的 `0916_ground_truth_current.json`；指標＝Top-1/3/5（以節點判定）。
> 部分方法另做 5-fold 交叉驗證（依節點分組）確認非過擬合。

---

## 1. 問題定義
給一張查詢照片 → 在 59 節點地圖（5 條平行走道、236 張「節點×方向」照片）裡判斷你在哪個節點。
做法＝對每個候選算相似度分數 → 排名 → 取最高。各方法差在「用什麼訊號算相似度」。

## 2. 最終結果（全部方法，同一測試集）
| 方法 | Top-1 | Top-5 | 備註 |
|------|:---:|:---:|------|
| 系統現況＝WGM 九宮格(字串)（實跑）| 28% | 55% | 目前部署、最弱 |
| 九宮格 + embedding | 33.6% | 56% | 換 embedding +8 分 |
| 物件 Node-only(embedding，無格無關係) | 32.8% | 56% | 格子其實可有可無 |
| GraphMatch 物件關係（粗糙/上游豐富/只商品）| 31% | 54% | ✗ 都 ≤ 不用關係 |
| 物件 + OCR | 41% | 63% | OCR 有效 |
| CLIP 視覺-only | 40% | 72% | — |
| **CLIP 融合（視覺+物件+OCR, CV）** | 55% | 84% | — |
| DINOv2 視覺-only | 60% | 87% | 換強視覺模型大躍進 |
| **DINOv2 融合（CV, 權重5:0.5:0.5）** | **66%** | **90%** | 🟢 **目前最佳** |

交叉驗證：DINO 融合 val 66.2%±6.3、全資料 65.7% → **幾乎零過擬合**，權重 5 折都是 (5,0.5,0.5)。

## 3. 各元件最終判定（關鍵）
| 元件 | 定位準確率 | 其他用途 | 結論 |
|------|:---:|------|:---:|
| **視覺 (DINOv2)** | ★★★ 主力 | — | **核心** |
| 九宮格 (WGM) | ✗ 被取代 | 無 | **可丟** |
| 物件關係 (graph matching) | ✗ 測3種都沒用 | 此環境無 | **可丟** |
| 物件 (objects) | 🟡 +2.6 分 | 目標導航、語意搜尋、可解釋、抗變化 | **留（為導航）** |
| OCR | 🟡 小 | 抗促銷/光線變化、分辨近乎相同點、可解釋 | **留（便宜保險）** |
| 拓樸圖 (walkway) | ✗ 單張用不到 | **路徑規劃核心** | **留（導航必需）** |

**一句話：定位主力＝視覺(DINO)；九宮格、物件關係可丟；物件/OCR/拓樸圖對 Top-1 貢獻小，但撐起導航/抗變化/可解釋。**

## 4. 已確認結論（含「為什麼」）
- ✅ **視覺模型是最大槓桿**：CLIP→DINOv2 讓純視覺 40%→60%，證明之前瓶頸就是視覺模型太弱。
- ✅ **embedding > 字串**（物件/九宮格比對 +7~8 分）。
- ✗ **物件關係沒用**：超市「排列同質、內容區分」，每條走道排列都一樣 → 關係無鑑別力；且與「有哪些物件」重複。測了粗糙/上游豐富/只商品三版都 ≤ 不用關係。
- ✗ **九宮格的「格子」中性**：用 embedding 後有格無格差不多。
- ⚠️ **方向(前後左右)不能用於部署**：label 是相對的（各點 heading 散佈 116°），且單張查詢**不知道方向**。同方向限制看似 63%，但部署拿不到方向資訊 → 真實值仍是自由比對。
- ⚠️ **純視覺怕「換」**：促銷換檔、光線、人潮、地圖過期都會讓視覺失準 → 需 OCR/結構當後盾 + 定期重拍地圖。
- 🎯 **定位 ≠ 系統目的**：系統要做「購物導航」。視覺負責「我在哪」；物件/OCR/拓樸圖負責「這裡有什麼、怎麼走、為什麼」。

## 5. 後續測試規劃
### 建議起點（新實驗一律以「DINO 融合」為對照基準）
視覺為主力，從視覺模型往上疊：DINO視覺 → +物件 → +OCR。

### 優先清單
| 優先 | 測試 | 目的 | 成本 |
|:--:|------|------|------|
| P0 | **把 DINO 融合接進正式 `locate_v2` 並實跑** | 驗證 66% 在正式 pipeline 成立 | 中 |
| P1 | **更強視覺模型**：DINOv2-large / **AnyLoc**(DINO+VLAD, 地點辨識SOTA) | 視覺還有空間 | 中 |
| P1 | **兩階段 re-rank**：視覺先篩 Top-K(已90%) → 物件+OCR 重排 | 把 Top-5 轉成 Top-1 | 低 |
| P2 | **互補性分析**：純視覺失敗案例，OCR/物件救回多少 → 決定留不留 | 定留/丟 | 低 |
| P2 | **跨店/跨時間泛化測試** | 確認非單店僥倖、驗證抗變化 | 需新資料 |
| P3 | 連續定位 + 拓樸圖約束（需移動情境）、更密視角建圖 | 砍遠方 aliasing | 需重採集 |
